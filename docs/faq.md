# 常见问题

## 名字为什么叫 Aletheia？

**Aletheia** 来自希腊文 **ἀλήθεια**，读作 /əˈliːθiə/（阿-勒-忒-娅）。它由否定前缀 *a-*（不）与 *lethe*（遗忘、遮蔽）组成，字面意思是把被遗忘、被盖住的东西重新取出来。海德格尔后来用这个词讲「真理」：让事物从遮蔽中自行显现。

漏洞分析在这里被理解成去蔽，而不是对运行中系统的进攻。命令行因此叫 `aletheia`。

## 这和 nmap / 在线漏洞扫描有什么区别？

本工具不向端口发探测包，也不登录远程服务。它只读源码和配置文本。要做运行时检测，请使用你被授权的 DAST 或集成测试，而不是把这个 CLI 改成攻击客户端。

## 为什么扫描 Aletheia 自己会报夹具和规则文件？

`fixtures/` 和 `test/` 里是故意写出来的不安全片段，用来验证规则。`src/rules/catalog.js` 里的正则字面量看起来也像危险代码。从本仓库根目录运行 `aletheia scan .` 时，仓库自带的 `aletheia.config.json` 会跳过样本目录；引擎在 JavaScript / TypeScript 中也不会把正则字面量当成真实 sink。

若要检查夹具是否仍能被检出，请显式扫描它：

```bash
node bin/aletheia.js scan ./fixtures/sample-web-service
```

## 为什么扫描 node_modules 没有结果？

默认忽略依赖目录。第三方包体积大、误报多。若你明确要审计某个依赖源码，把该包拷到扫描目标并在配置里收窄 `include`。

## 可以扫描编译后的 `.class` 或二进制吗？

不可以。只处理文本源码与常见配置。Java 请扫描 `.java`，前端请扫描未压缩的源文件。

## JSON 报告能否当 API？

可以。`scanProject` 的返回对象与 `--format json` 一致。字段稳定性见开发人员手册。SARIF 用于平台集成，不建议手写解析。

## 如何只扫描变更过的文件？

把文件列表作为多次 `scan` 的单文件目标，或生成一个临时目录。当前版本没有内置 `git diff` 模式，以免把 git 操作耦合进核心。

## 规则会不会执行我仓库里的代码？

不会。规则是正则匹配。目标项目的 `package.json` 脚本、Makefile 都不会被执行。

## 出现大量 `weak-crypto` 怎么办？

校验和、缓存 key 使用 MD5 很常见。可用 `--disable weak-crypto` 或把测试夹具排除出扫描路径。密码存储仍应使用专用 KDF。
