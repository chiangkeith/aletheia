# 常见问题

## 名字为什么叫 Aletheia？

希腊文 ἀλήθεια 的字面义是「从遗忘与遮蔽中取出」。漏洞分析在这里被理解成去蔽，而不是对运行中系统的进攻。更完整的说明见 [README 命名一节](../README.md#命名)。

## 这和 nmap / 在线漏洞扫描有什么区别？

本工具不向端口发探测包，也不登录远程服务。它只读源码和配置文本。要做运行时检测，请使用你被授权的 DAST 或集成测试，而不是把这个 CLI 改成攻击客户端。

## 为什么扫描 node_modules 没有结果？

默认忽略依赖目录。第三方包体积大、误报多。若你明确要审计某个依赖源码，把该包拷到扫描目标并在配置里收窄 `include`。

## 可以扫描编译后的 `.class` 或二进制吗？

不可以。只处理文本源码与常见配置。Java 请扫描 `.java`，前端请扫描未压缩的源文件。

## JSON 报告能否当 API？

可以。`scanProject` 的返回对象与 `--format json` 一致。字段稳定性见开发人员手册。SARIF 用于平台集成，不建议手写解析。

## 如何只扫描变更过的文件？

把文件列表作为多次 `scan` 的单文件目标，或生成一个临时目录。当前版本没有内置 `git diff` 模式，以免把 git 操作耦合进核心。

## 规则会不会执行我仓库里的代码？

不会。规则是正则匹配。目标项目的 `package.json` 脚本、Makefile 都不会被执行。

## 出现大量 `weak-crypto` 怎么办？

校验和、缓存 key 使用 MD5 很常见。可用 `--disable weak-crypto` 或把测试夹具排除出扫描路径。密码存储仍应使用专用 KDF。
